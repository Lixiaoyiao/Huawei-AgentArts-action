## 本项目如何回应赛题

场景是开源仓库维护者处理 PR 审查、CI 故障和 Issue 需求。第一期只完成 PR Review：维护者通过 GitHub 的真实任务启动，在 AgentArts 上运行固定版本 DSH，控制端独立检查返回结果，再在绑定的 PR 中发布审查建议。关键技术问题是云端上下文、进程与凭证隔离、真实工具回执、结果校验、停止与重复运行边界。

高代码 Runtime 路线是本项目结合官方能力作出的技术选择，仍需要实际租户验证。赛题正文没有限定低代码，也没有把多 Agent、独立知识库、MaaS 或 CodeArts 分别列为赛题 2 的必选项。这里继续保留 DSH 和 DeepSeek，围绕真实任务体现 Runtime 托管、工具执行治理与效果验证；是否加入 Gateway/MCP，以可用能力和具体业务价值决定。

## 各阶段材料

初赛提交 Word 作品信息表，准备场景、创意、团队、Agent 架构、模型/资产选择，并用视频展示基于 AgentArts 构建与运行的完整流程。评分为创新性 60%、应用价值 40%。当前本地和容器演示可用于说明实现与边界，不能替代该完整云端流程。

中国总决赛需要答辩 PPT、可在线访问和交互的 Demo、设计方案及模型/语料方法说明；自定义 Skill/MCP 如有则说明，同时准备作品分享截图。评分为创新性 40%、应用价值 35%、完整展示 15%、答辩 10%。全球总决赛还需实际应用进展与社区反馈数据，评分为 40%、30%、15%、10%、5%。这些是评分权重，不是本项目已取得的分数。

## 接下来的顺序与验收

1. 使用已有或明确批准的资源完成固定镜像的真实 Runtime 验收。若 root supervisor/独立 UID、元数据凭证边界、出站模型访问或超时清理不成立，停止上线并评估替代运行方式。
2. 安装新仓库的受信 PR Review workflow，跑真实 GitHub → AgentArts → DSH → 控制端独立验证 → GitHub 评论。保存平台运行记录、Session/task/head 绑定和结果链接。
3. 跑 [业务任务集](evaluation.md)，由维护者根据固定代码与 diff 判定发现是否正确；同时验证拒绝、提交变化、超时、取消和评论去重。
4. 将脱敏的真实记录用于 Demo，准备在线交互展示。部署文件可以先生成，创建付费资源或公开发布仍单独确认；历史文件清楚标为回放。
5. 再增加有业务意义的 Gateway/MCP 与平台评估，分别记录实际平台贡献与业务验收结论。之后扩展 CI 修复和 Issue→PR，重新验证补丁返回、独立测试和发布边界。
6. 按 [演示指南](demo-guide.md) 整理技术方案、视频与分享内容。真实使用数量、模型结果、社区反馈和费用均取实际记录，未知项保留未知。

本届规则还提到审核通过后按队伍提供云资源支持，预计 10 月启动代金券申请；额度、适用范围和有效期以组委会通知为准。页面区域接口的 `uploadWorkDeadline` 不直接当作初赛截止日期。项目不会自动购买服务、申请券或提交比赛材料。
